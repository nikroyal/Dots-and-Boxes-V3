## 2025-02-25 - Prevent DoS and Leaderboard Cheating in Firestore Rules
**Vulnerability:** Missing input validation allowed users to create accounts with artificial `elo: 999999` and submit massive string payloads (e.g., to DMs, clubs, or bio fields), leading to database bloat, egress spikes, or DoS attacks.
**Learning:** In a heavily client-reliant serverless architecture, Firestore Security Rules are the only backend defense. Properties modified directly by the client (like `elo` and `messages`) must have boundary rules applied on `allow create` and `allow update` instead of blindly trusting client input.
**Prevention:** Always add boundary and type constraints (`is string`, `.size() <= 1000`) for user-generated strings, and validate critical defaults during document creation (`get('elo', 1000) <= 1000`).
